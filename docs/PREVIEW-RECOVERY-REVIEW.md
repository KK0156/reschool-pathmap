# Codespacesプレビューの配信確認と別ポート起動

2026-10-20。基準コミット：`4a859a9`。

## 報告と確認範囲

利用者から、ChatGPT内の表示に加え、Chromeで直接開いた8000番のプレビューも白画面になると報告された。画像にはアプリの起動案内が表示されていない。アプリ内ブラウザだけの問題とは判断できない。

こちらからその私有プレビューにアクセスするとGitHubの認証へ転送され、Codespaces APIも連携の権限不足を返す。利用者がログイン済みのブラウザや、利用者のCodespace内の8000番を直接調べることはできない。こちらの別環境で起動できた結果を、その私有Codespacesの復旧確認として扱わない。

既存の開発サーバーはリクエストごとにファイルを読み、`Cache-Control: no-store` を指定している。同じ作業ディレクトリを配信しているなら、フロントエンドの変更のために再起動する必要はない。`EADDRINUSE` だけでは、古いコードや別のサーバーだと断定できない。

## 追加した操作

```sh
npm run preview
```

- 同じCodespace内の8000番を読み取り専用で確認し、HTTPステータス、Content-Type、本文のバイト数、作業中のファイルとの一致を表示する。
- 既存のプロセスを終了せず、8001番から空いているポートを探して別のサーバーを起動する。
- 起動する場所はスクリプト自身があるリポジトリに固定する。
- 配信するHTMLと代表的なJS・CSSを確認してからURLを表示する。
- Codespacesの環境情報が正しく取得できた場合に、そのCodespaceと選択したポートのURLを表示する。他のCodespace名を固定して配らない。
- 有料AIはプレビュー中無効にする。ポートの公開範囲を変更しない。
- 停止するのは、この操作が起動した子プロセスだけにする。

診断のために相談内容、環境変数一覧、Cookie、APIキー、HTTP本文、プロセスの引数一覧を出力する必要はない。

## 残る確認

このコマンドの確認範囲は、実行した環境内の配信内容と、自分で起動したサーバーの応答である。GitHubのポート転送や認証、利用者のブラウザでの描画の復旧を保証しない。これらは、利用者のCodespaceでの診断結果と新しいURLでの挙動をもとに次に切り分ける必要がある。

利用者のCodespace内では、こちらから操作できる権限がないため一度の実行が必要になる。原稿、JSONファイル、研究資料、旧試作品のデザインは変更しない。
