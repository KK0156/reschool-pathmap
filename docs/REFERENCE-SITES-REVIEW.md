## 開発で複数サイトを参考にする

[参考サイトの設計ガイド](REFERENCE-DESIGN-GUIDE.md) に、参考元の仕組み、Finderへの適用先、持ち込まない点、確認範囲を整理しました。READMEとDESIGNから参照できます。UIを変える前に、改善する場面に対応する一次ページを開き、採用理由と実画面の確認結果を残す手順です。

学問・仕事・制度の内容、質問の進め方、全体図と現在地、比較、次の行動を別の観点で検討します。海外サービスの資格・給与・募集条件を日本の生徒へ転用せず、学校の掲示板・紙・深緑という見た目を維持します。

## 生徒が複数サイトで調べる

ホームの「参考サイトからも調べる」で一覧を開けます。道の説明や比較からは「この道の参考サイト」を開きます。関連する道のIDを使う選択であり、本人の適性・合格可能性やサイトの優劣を判定するものではありません。

- 発行元、情報の種類、何を調べられるか、そこで確かめたいことを表示します。
- 学問・授業、仕事・働き方、制度・費用、学校外・海外の分類で絞れます。
- 関連サイトと一覧を行き来でき、最初の6件の後にも参照先があることと件数を示します。一覧の先頭には読み始めやすい仕事・学問・費用・オンライン学習の入口を置き、制度資料だけが続かないようにしました。
- 経済学・数学・デザインでは、今回確認した対応する詳しいページを使います。Webデザインはデザイン全般の代わりではなく、仕事の一例です。
- 案内ページの確認日・範囲・未確認事項は折りたたみで読めます。資料ページを見た日と、最新条件や本人の利用資格を確認した日は別に扱います。

リンクは本人の操作で別タブに開き、`noopener noreferrer` を付けます。回答・本人メモ・閲覧状態をURLへ付けません。資料を読む間はTreeを一時的に隠して文章の場所を確保し、戻ると同じ道・比較・Tree・本人メモを表示します。参考サイトの絞り込みは補助画面の状態で、既存の探索状態を置き換えません。

### 確認したいことをメモへ残す

各サイトの「確認したいことをメモへ」は、既存の道ごとの確認メモへ、サイト名・URL・確かめたい問いを「これから調べる」下書きとして追加します。複数サイトを残せます。同じURLは二重追加しません。

元の文章、本人の確認状態、公式ページ欄、本人が読んだ日付は保ちます。サイトを開いたことや下書きを追加したことだけで、資料を読んだ・条件が確認されたとは扱いません。700文字を超える場合は追加前に止め、既存メモを切り捨てません。

下書きは既存のFinder JSON v1/v2の `recordDrafts` を使って保存・復元できます。新しい参考サイトのIDを、制度説明の出典IDや `catalogueSources` へ混ぜません。既存Treeの形式も変更しません。参考サイトの補助画面とその絞り込み自体は保存対象に追加していません。

## 実画面を見て修正した点

1. 一覧の最初の6件が制度資料だけに偏っていたため、仕事・学問・支援・授業の入口を先に置きました。関連する道の参照先の順序は維持しています。
2. スマートフォンで長い道の名前を見出し・説明に繰り返し、最初のカードが画面外へ押し出されていました。見出しを短くし、分類は必要時に開く形にしました。
3. 参考サイトの見出しへスクロールすると、戻るボタンが固定ヘッダーの下へ隠れました。戻る操作から表示し、中心を実際に押せることを確認しました。
4. 道を押してもスマートフォンではTree・分類が先に出て説明が見えなかったため、通常の表示では選んだ道の見出しへ移動するようにしました。地図を大きく見る表示を本人が選んだ場合は維持します。
5. メモ追加後の入力欄だけが画面上端へ移動し、ラベルと新しい追加分が見えにくかったため、ラベルの位置を保ちながら入力欄の末尾を表示する調整を加えました。
