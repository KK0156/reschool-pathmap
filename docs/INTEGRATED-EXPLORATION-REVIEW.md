## Phase A：現行実装の監査

既存の案内は、相談→道→比較→メモという順番を表示するが、Treeは別の任意画面へ引き継ぐ方式だった。そのため、質問に答えている間は自分の回答と道の関係を地図で確認できず、Atlasの詳細や比較とTreeの選択も連動していなかった。

状態の所有者は次のように分かれていた。

| 部分 | 保持していたもの | 統合時に守ること |
| --- | --- | --- |
| AI対話 | 回答・訂正・現在の質問・書きかけ・同意・リクエスト識別子 | 地図の描画で再初期化しない。送信は毎回本人が確認する |
| Atlas | ルートID・閲覧履歴・比較・残した候補・確認メモ | 一般資料の文章をAIや本人のメモで上書きしない |
| Finder | 画面の行き来・本人メモ・保存確認 | Treeを使わなくても持ち帰れるようにする |
| 既存の自由編集Tree | 項目・本人編集・Undo・座標・下書き | 自動更新の対象にしない。明示的な置換の確認を維持する |

## Phase B：共通探索モデル

`src/exploration-model.js` のstoreへ、確定した対話・Atlas・本人メモのスナップショットと、地図の編集状態を集める。未反映の入力や通信制御は従来の画面に残し、地図の更新から質問・同意を復元し直さない。

```text
本人の回答・訂正 ─┐
受け取ったAIの整理 ├→ 共通探索store → RE:Treeの表示
AtlasのID・閲覧・比較┤                 → 選択した項目の文章
本人のメモ・行動 ─┘                 → 保存前確認とFinderファイル

Treeの枝を選ぶ → 同じAtlas IDの説明を開く
文章から道を開く → 同じTreeノードを選択・展開する
```

一般的なルート本文はAtlasの一か所に置き、地図は `atlas-<Atlas ID>` で参照する。75項目を別の独立した進路データとして複製しない。階層の枝と、関連・組み合わせ・移行の接続を分けて表示する。

地図の状態は `expanded`、`selected`、`emphasis`、`notes`、`overrides`、`positions`、`serial`、`step`。回答やAIの整理が増えたときに必要な枝を一度開き、同じ応答の再描画でノードを増殖させない。本人が閉じた枝を、同じ内容の再通知で開き直さない。

本人の編集は一般資料の上書きではなく、IDに対応する別の注記として保持する。編集したAI項目が次の応答から消えても、本人の言葉は残る。地図用Undoは本人の編集だけを戻し、新しい回答・AI応答・比較・現在の段階を巻き戻さない。

## Phase C・D：一連の体験

案内を5段階にそろえた。順番は強制せず、質問なしで全体を見る、比較を飛ばす、未定のまま終える操作を維持する。

1. **自分を知る**：一問ずつの回答・AIの解釈・本人の訂正を別の枝にする。「ここまでの話の整理」や枝の文章でも確認できる。「今の状況」「大切にしたいこと」等は整理のための区分であり、本人を診断した属性ではない。
2. **可能性を広げる**：就職、専門的な教育、大学・短大、海外、活動・探索期間、働きながら学ぶ、後から学ぶという入口を残す。AIの注目候補を示しても、他の道を消さない。
3. **道を深く知る**：Treeから既存Atlasの詳細を開き、文章の関連ルートからもTreeを選択する。既存8項目、条件・出典・未確認状態を再利用する。本人が地図を書き直した場合は、本人の注記と元の一般資料を並べて読む。
4. **比較して考える**：二つの道を同じ8項目で比較し、Treeにも比較中の表示を付ける。順位・適性・合格可能性は出さない。現行の比較上限は二つで、任意の他の候補へ選び直せる。
5. **次の行動を整理する**：気になる道、最近開いた一般資料、まだ分からないこと、AIの未確認の行動案、本人の気づき・行動メモを区別する。本人が書いたメモも地図へ反映し、Path Finder内で保存・再開する。任意で「AIと、ここまでを整理する」を選べる。新しい送信内容の確認・今回の同意後に既存の要約動作を要求し、応答後は本人メモを保って行動画面へ戻る。

PCは地図と文章を横並びにし、iPad相当では地図の下に文章を置く。スマートフォンは縦配置で、地図をコンパクトに表示する。「地図と文章」「地図を大きく」「文章を中心に」を同じ状態のまま切り替える。長文をノードへ詰めず、詳細は読む面へ分ける。

### 保存と互換性

- Finder v1は引き続き検証・復元できる。新しい共通地図の状態を含む場合だけ、同じ `repath-finder-session` の `schemaVersion: 2` で保存する。
- v2も最大1MiB。版、正確なキー、Atlas ID、出典の対応、手動ノードの関係、循環、文字長、座標、危険なプロパティを検証する。不正なファイルで現在の探索を変更しない。
- 質問への回答は通常省く。本人が反映した訂正、地図の注記、本人メモは残ることを保存前に表示する。AIの整理にも発言由来の内容が含まれ得る。回答を省いた復元では、元の回答を創作しない。
- 反映前の地図編集はファイルに黙って落とさず、保存・Tree出力・復元を止め、反映するか書き直しをやめるよう案内する。入力は保持する。
- 参照資料を一部だけ含む有効な旧ファイルを読み、その後に新しい道を探索した場合は、不足する現行Atlasの資料を追加する。読み込んだ資料の確認日・記録を上書きしない。
- 既存Tree JSON v1は変更しない。探索地図からTree v1の階層の写しも出力できる。長い本人メモは続きの項目へ分け、黙って切り捨てない。200項目を超える場合はFinder形式へ案内する。横断接続・比較・探索の再開にはFinder形式を使う。
- 従来の自由編集Treeを自動で置き換える処理はない。既存の手動編集・Undo・配置・ファイル入出力を維持する。

### 送信と状態の境界

同意、プレビュー、リクエスト識別子、revision、タイムアウト、取消は従来の対話処理を維持する。地図の枝を選ぶ・編集する・比較する・保存するだけでは外部AIを呼ばない。AIの新しい質問や説明は、既存Functionへ本人が同意して送ったときに要求する。

共通storeから各画面を無条件に復元することはしない。ファイル復元では全体を検証して確認を得た後にまとめて置き換え、中途半端な状態を公開しない。復元中に対話の更新通知が発生しても、古いメモと新しい地図を混ぜない。

## Phase E：実画面から修正した点

- 最初の統合では読む面の見出しへスクロールし、Treeが画面外へ消えた。狭い画面のバランス表示では地図と読む面の始まりを一緒に見せるよう調整した。
- Treeのノードが増えても枠内の古い位置が残ったため、新しい回答・AIが注目した道・行動の位置を地図内で見せるよう調整した。本文へのキーボードフォーカスを奪わない。
- iPad相当では手動フォームを開いた地図が詳細を隠した。詳しい地図操作を開いている間は固定表示を解除し、詳細・子の道へのスクロール余白を調整した。
- 5段階の見出しが狭い画面で不自然に一文字だけ折り返したため、スマートフォンの表示名を短くした。
- 保存前に残っていた未反映の手書きを検出し、黙って未保存のままファイルを作らないようにした。
- 削除の確認が二度出る、明示的に閉じた枝が再び開く、長いメモがTree出力で切れる問題も修正した。

## 残る検証

- 実AIが作る問い・説明・新しい道の関連性と事実性は未検証。
- WebKitとタッチ入力はブラウザの検証であり、iPad実機/Safari、実際の読み上げ支援技術の検証ではない。
- 高校生が説明なしに操作できるか、本人の理解や選択肢の発見に役立つかは、実際の操作観察が必要。
- 共通地図は読みやすさのため自動配置する。従来の自由配置キャンバスは既存Treeとして残るが、自由編集した別の図から探索状態へ逆変換する機能は追加していない。
- AIへ送るのはプレビューに示す回答・訂正・比較するAtlas ID。地図の手書きや本人メモを含む再相談は、自動送信を避けるため追加していない。
- 320pxでは、回答後に見える説明の最初の行は約87%。長い文章は縦にスクロールして読む。1024×768の横向きは初回を検証し、全詳細や比較を同時に表示できると確認したわけではない。
- Atlasの制度・資料の確認状態は既存の範囲を維持し、最新募集や本人の適格性を調べ直したとは扱わない。

### 検証後の指示更新

ユーザーから「pushして毎回」と追加指示を受けた。このリポジトリでは、修正・検証が完了した変更はコミットし、GitHubへpushする。以後、pushのたびに再承認は求めない。ユーザーから保留・中止の指示があればそちらを優先する。

上記の「未コミット・未push」はローカル検証終了時点の記録であり、その後の反映状態はGit履歴と作業完了時の報告で確認する。Netlifyの手動デプロイ、有料APIの実行、非公開資料の公開は、この追加指示の対象に含めない。
