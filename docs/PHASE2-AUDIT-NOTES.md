# Phase 2 — Research / Security audit notes

2026-10-20。実装担当向けの監査メモ。最終結果は `docs/PHASE2-REVIEW.md` に統合する。

## 研究資料の確認と変更

確認対象：README.md、DESIGN.md、docs/LOCAL-REVIEW.md、src/research-data.js、src/desk-app.js、旧試作品、共有ツリー実装とテスト。未反映の `docs/RESCHOOL-PROJECT-REVIEW.md` は上書き・削除しない。

`src/research-data.js` の7段階・ID・既存の説明は維持し、各段階に `evidence` を追加した。`researchEvidenceLabels` が表示名を定義する。

- `fact`：確認された事実。主として、リポジトリに説明や試作が存在すること。調査対象の社会的事実を確認したという意味ではない。
- `observation`：本人の研究経緯・観察として記述されたこと。原記録の掲載状況を併記。
- `hypothesis`：試すべき説明。
- `counterargument`：別の説明・反論。
- `unresearched`：未調査・未確認事項。
- `prototype`：試作したもの。
- `tested`：コード操作の確認と、利用者への効果の検証を区別。
- `sources`：`{label,path,availability}` の配列。`present` は資料や実装の存在、`not_published` は未掲載、`not_verified` は確認していないもの。未掲載は未実施を意味しない。

出発点は日米の教育機会・資源比較。社会全体の安全・秩序・信頼・開放性は後の比較の広がりとして維持する。教頭インタビューの逐語録・実施日・発言・公開同意を確認できないため、内容を補っていない。

`interviewFollowUp.problemStatus` と `nextInterview` を追加し、「次の元教員インタビューが終わるまで問題の最終特定を保留」と明示した。実施日、対象者、発言、結果は作っていない。「教員の事務負担が最大原因」「AIが最適解」とは結論づけない。

## Git履歴の限定的スキャン

現在見える全refに対し、`git rev-list --objects --all` で列挙した233個の履歴blob（計2,583,553バイト）を走査した。OpenAI形式のキー、GitHubトークン、AWSアクセスキー、秘密鍵ヘッダー、メールアドレスのパターンに一致する内容は検出しなかった。追跡中67ファイルには、`.env`、秘密鍵のようなファイル名も見当たらなかった。値は出力・記録していない。

これは「秘密情報がない」という証明ではない。独自形式・エンコードされた秘密、削除済みでrefから到達できないオブジェクト、GitHub側のログやPR、外部ストレージ、プラットフォームの設定は対象外。人名や学校名が非公開情報かどうかを自動パターンだけで判定することもできない。現在のケース・学校は架空と明示されているが、実際の公開許可や原資料は別途確認が必要。

## Phase 2で維持・追加確認が必要な点

1. AIの整理や提案へ、既存ツリー全体や任意の成績欄を不要に送らない。選択部分の送信前プレビューと、提案専用の同意が必要。
2. AI提案は本人の承認前に既存項目へ上書きしない。待機中の編集・消去・移動・インポート後に古い応答を反映しない。由来は読み込み後も検証済みに昇格させない。
3. 接続設定の有無の表示は、キーの文字列を返さない。設定済みは利用枠や回答品質の確認ではない。
4. ブラウザ内の消去は、既にダウンロード・コピー・印刷したデータを削除するものではない。持ち帰る前の確認を案内する。
5. `store:false` はAPI提供者・ホスティングの全ログをゼロにする保証ではない。Netlify側のアクセスログ、IP、エラー収集、AI提供者の保持は今回のコード監査では確認できない。
6. 自由記述に本人が個人情報を書けば、同意した送信に含まれ得る。名前を出力しないプロンプトだけでは、入力の匿名化を保証しない。
7. 公開時のレート制限はNetlifyの設定・実行環境での確認が必要。ローカルで本番DDoS・認可を検証したとはいわない。
8. 有料APIは呼んでいない。モックで通ることと、実際のAI出力が常に安全・正確であることは別。

## コードレビューの初期所見

既存のJSON読み込みとHTMLエスケープには、現在の用途に対し維持すべき保護策がある。大規模な作り直しは不要。最も重要な不足は、研究ノートの「資料の存在」と「効果の検証」を段階ごとに読めること、AIの追加提案の承認・由来・状態管理、実際の先生や生徒による検証の切り分けである。
