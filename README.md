# RE:Path Finder — まだ知らない道を、一緒に探す

大学へ進学するかまだ分からない高校生も、学び方・働き方を見渡し、生活や条件、その先の道を比べられる研究プロトタイプです。質問に答えず全体マップを開けます。AI相談と、考えを図にするRE:Treeは任意です。学校の研究室・掲示板・ノートの見た目と、RE:Schoolの研究報告を維持しています。進路・適性・合格可能性は判定しません。

- `/`：ホーム。まず全体を見る入口、7つの卒業後の道、3つの読み方の例。従来のAI相談と固定デモも残す
- `/#/finder?mode=all`：全体マップ。卒業後の道・学問分野・学び方・学校内外の経験を、段階的に開く。生活・費用・収入など8項目で2つの道を比較
- `/#/finder?mode=ai`：任意のAI相談。3画面の簡単な入力から、今回AIが注目した3〜5候補を読む。ここにない道も全体マップに残る
- `/#/cases`：事例を見る。一般の生徒の悩みを扱う12の架空ケースから、その例のツリーへ進む
- `/#/research`：研究について。RE:Schoolの研究報告13章、資料の確認範囲、日米の教育比較を起点とする7段階の年表
- `/#/archive`：開発の歴史。旧試作品の目的・機能・残った問いと、当時のデザインの保存画面
- `/#/tree`：RE:Treeで整理する（任意）。選んだ候補を引き継ぐか、既存の相談例・白紙から編集・行動計画・JSON保存／復元を使う

開発者の7つのテーマを扱っていた`/#/choices`はメインナビゲーションから外し、RE:Schoolに関係する検討案を研究報告へ移しました。ROOTSは独立したプロジェクトで、RE:Schoolの研究成果や専用研究テーマには含めません。過去の開発者用デモはアーカイブで区別して保管しています。

全体マップは就職、専門教育、大学・短大、海外、活動・探索の期間、働きながら学ぶ、後から学ぶ道を同列に扱います。分類・一般ルートを含む75項目、階層と横断の86接続を収録しています。全ての生き方・制度・個人の可能性を網羅した分類ではありません。公式資料12件を参照し、制度があることと本人の利用条件を分けています。

3つの操作例は「まだ決まっていない」「文理をまたぐ」「大学・短大の中身」。一段目から本人が操作して3階層へ進めます。以前のAI相談の固定デモ4種類（各17候補）も保持しています。どの例も本人の入力を分析した結果ではありません。選んだ道をRE:Treeへ任意で引き継ぎ、編集・JSON保存・復元できます。

既存のRE:School v1は `/original.html`、Path Map試作品3号は `/reschool.html` に維持しています。Prototype 2本体とEvidence Packのファイルは未掲載で、Coming soonと表示します。試作品3号をv2と偽って掲載しません。

## AIとの相談

1. 三つの質問で選択する
2. 外部AIへ送る内容を確認し、同意して送信する
3. AIの返答、参考に読む分野、先生に聞く項目を読む
4. AIが選んだ追加質問に、用意された選択肢で答える
5. 最大6回の返答の範囲で相談を続け、必要なら先生に見せる用に印刷する

サイト → `/.netlify/functions/path-consult` → OpenAI Responses API、という構成です。AIの返答は実際のAPIから取得し、未設定時にサンプル回答をAIの返答として表示することはありません。標準モデルは `gpt-5-mini`。`OPENAI_MODEL` で対応モデルに変更できます。料金は利用するAPIとNetlifyのプランに従います。

AIには進路・適性・合格可能性・将来性を判定しないよう指示しますが、誤りや断定を完全には防げません。入試・資格・費用は、先生と公式資料で確認する項目として扱います。参考資料は16分野と架空の卒業生事例に限られ、最新情報を検索する機能はありません。

APIを使わない「選択だけでサンプルを絞る」機能も残しています。タグの一致による検索であり、AIの返答とは区別しています。

## 送信・保存・安全

- 名前・実際の学校名・連絡先の入力は不要。相談メモと、成績の目安・科目・希望条件等の任意欄がある
- 選択式相談のサーバーは許可リストと追加質問のID・回答番号のみ受け付ける。ツリー生成のサーバーは、相談メモと任意欄をまとめた3000文字以内の文章のみ受け付ける
- 選択式は選択肢と追加質問への回答のみ送信。ツリー生成では確認済みの相談メモと記入済みの任意欄のみ送信。編集したツリー、先生用メモ、学校選択は送信しない
- 会話はブラウザのメモリのみで、消去・再読み込みで消える
- Cookie、localStorage、sessionStorage、解析、会話のDB保存を使わない
- OpenAIには `store:false` を指定。API提供者側のログ・保持・データの扱いは別であり、ゼロ保持の保証ではない
- アプリのコードはキー・会話・API応答をログに出さない。Netlify等のプラットフォーム側のアクセスログはその管理範囲
- APIキーはサーバーの環境変数のみ。ブラウザへ渡さない
- リクエスト本文・会話回数・出力を制限。同一オリジン確認、タイムアウト、Netlifyのレート制限を設定
- 外部の大人との対話は先生・学校・保護者を通す。直接連絡・予約・申請送信はない

この改訂で、旧要件の「API通信を使わない」はAI相談に限って変更しました。他の資料機能にはAPI通信は不要です。

## Phase 3 — 一般の高校生の入口と、研究報告を分ける

変更と検証の詳細は [docs/PHASE3-REVIEW.md](docs/PHASE3-REVIEW.md) に記録します。ホームから相談例を開く、内容を手直しする、枝を足す・消す、次の一歩を書く、JSON保存して続きを復元する、という一連の操作を優先しています。AIへの送信は必要ありません。

- `/#/tree?sample=humanities-science`：文理選択の編集できる架空の例。
- `/#/choices`：研究報告の検討案へ移動。一般向けの進路比較一覧としては表示しません。
- Phase 3当時の`/#/finder`、`/#/paths`はツリーへの案内でした。Phase 4では`/#/finder`が探索本体になり、`/#/paths`からも探索へ案内します。保存版のURLは維持します。
- `/#/dashboard`：開発の歴史へ移動。旧Path Mapの学校ページは`/reschool.html#/dashboard`に残ります。
- 一般向けの画面では、資料やリスクを詳しく書く編集欄・AIの追加相談・配置の詳細設定を、必要なときに開けます。旧保存版の機能表示は維持しています。

新しい検証は`tests/phase3-browser.py`、`tests/phase3-student-data.test.js`、`tests/phase3-report.test.js`です。既存のAI・JSON・キャンバス・保存版の回帰検証も引き続き行います。画面や操作の検証と、生徒・先生による使いやすさの評価は区別します。

## Phase 4 — 道を探す体験と、考えを整理する道具

変更ファイル・実画面・検証・未実装の詳細は [docs/PHASE4-REVIEW.md](docs/PHASE4-REVIEW.md) に記録します。

- 相談はテーマ、いまの迷い、条件と送信確認の3画面。プロフィール・成績は必須にしません。自由入力以外は文章未記入でも進めます。
- AI候補は最初3〜5方向。選んだ方向の深掘り、候補への質問は、その都度送信内容を確認し同意してから実行します。並び順は順位ではありません。
- 各候補に内容・含めた理由・学びや活動の例・条件・未確認事項・次の一歩を表示します。可能性を検討する道、条件確認が必要な道、現時点で判定できない道を文字で区別します。
- 最新の大学・入試・資格・活動を検索する機能はありません。公式情報を確認したような出典や確認日は付けず、一般的な候補として扱います。
- 2候補を同じ項目で比較でき、最大6候補を残せます。本人が希望すると、選んだ候補と確認事項をRE:Treeへ引き継ぎます。元の相談文や任意の背景欄は転記しません。
- 探索履歴と入力はメモリのみです。ページ間の移動では保持しますが、再読み込みで消えます。持ち帰る場合はRE:TreeでJSON保存してください。探索グラフ全体の直接保存は未実装です。
- 新しい`discover-routes` FunctionはPOST時のみOpenAIを利用します。GETは`configured`と`browsing:false`だけを返します。標準モデルは`gpt-4.1-mini`、`OPENAI_ROUTE_MODEL`、次に`OPENAI_MODEL`で変更できます。`store:false`を指定しますが、提供者側の保持やログをゼロと保証するものではありません。
- `PATH_MAP_OFFLINE=1`、`npm run preview`ではキーが設定されていても外部AIへ接続しません。ローカルでAIを接続する場合は、このオフライン指定を外してサーバー側にキーを設定します。今回の検証では有料APIは使っていません。

新しい単体検証は`tests/route-model.test.js`、`tests/discovery-api.test.js`、`tests/discovery-transfer.test.js`、操作検証は`tests/phase4-browser.py`です。全単体テスト・ビルドと、Chromium／WebKitでの探索・既存機能の回帰検証を行います。実際のモデルの回答品質、実機iPad、実利用者による評価は別途必要です。

## Phase 4追加 — 大学進学を前提にしない全体マップ

設計は [docs/ROUTE-ATLAS-DESIGN.md](docs/ROUTE-ATLAS-DESIGN.md)、参照先は [docs/ROUTE-ATLAS-SOURCES.md](docs/ROUTE-ATLAS-SOURCES.md)、実装・画面・テスト結果は [docs/ROUTE-ATLAS-REVIEW.md](docs/ROUTE-ATLAS-REVIEW.md) に記録します。

- 最初は7方向を同列に表示。学問分野・学び方・学校内外の経験の見方へ切り替え、分類→具体的な道へ進めます。単一の親だけでなく、関連・組み合わせ・移行の接続を持ちます。
- 希望、履修科目・気になる分野、時期、費用は任意の確認メモです。道を隠したり、向いている順に並べたりしません。
- 調べている状態は「検討中」「条件確認が必要」「未調査」「確認した制約（本人の記録）」。「確認した制約」にはメモ・HTTPSの出典URL・確認日を求めますが、アプリが本人の条件を検証したことにはしません。
- 比較は学ぶ内容、生活、費用、収入、条件、期間、その先の道、変更方法の8項目。全体図、直前の画面、開いた道・未閲覧の方向が分かるようにします。
- AI相談は明示して選んだときだけ準備します。全体マップだけの利用ではAI接続設定のGETも不要です。希望・確認メモを自動でAIへ送りません。
- AI候補とマップ項目の語句が重なると、キーワード参照として表示します。AIが他の道を排除したり、制度や本人の利用資格を確認したりした表示ではありません。
- 公式資料の確認日は、開いて読んだ資料の範囲に限ります。学校・求人・活動の最新の募集・費用・期限の自動取得や個別要件の判定は未実装です。
- マップの履歴・メモ・閲覧状態の直接保存は未実装です。必要な候補は任意でTreeへ渡してJSON保存できます。一般資料・本人記入・書き直しの由来も復元できます。旧JSON v1は引き続き読み込めます。

`PATH_MAP_OFFLINE=1 PATH_MAP_PORT=8002 npm start` で、AIへの有料接続を止めたローカルプレビューを使えます。新規検証は `tests/route-atlas-{data,model,reference}.test.js` と `tests/route-atlas-browser.py`。既存のPhase 4 AI探索・Tree・研究報告・保存版の回帰検証も行います。
